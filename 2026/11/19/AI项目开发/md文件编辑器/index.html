我用 Windows 自带的脚本引擎，写了一个 160KB 的 Markdown 编辑器

我想要的东西其实很小：一个双击就能打开、打开就能写、关掉不心疼的 Markdown 编辑器。

市面上的选择并不缺，但它们都太重了。Typora 要装，Obsidian 一开就是几百兆内存，VS Code 很好，可我每次只是想记三行字。

于是有了 MdStudio：161 KB 的单文件 exe，Windows 7 到 11 全都能跑，绿色免安装。

一、我给自己定的约束

先写死需求，再谈技术，否则一定会被”顺便加个功能”带跑：

  • 单文件，不安装，复制到 U 盘就能用；
  • 启动必须快，快到没有”等待”这个动作；
  • 支持 Windows 7（这条最狠，直接砍掉一半现代方案）；
  • 仿 Typora 的即时预览，但不要它的重量；
  • 能接管 .md 默认打开，图标要好看；
  • 主题、字体、字号可调，写起来顺手。

二、选型：我推翻了自己三次

第一次：Electron。

最顺手，也最先被否掉。一个空壳 Electron 就有 100 MB 起步，Win7 还要挑特定版本，启动两秒起。这和我想要的”轻”是两件事。

第二次：纯 HTA。

Windows 自带 mshta.exe，一个 .hta 文件就是窗口 + 网页 + ActiveX，写文件、读注册表全都能做。成品 122 KB，双击即开，速度无可挑剔。

但它有两个致命问题：

  1. 文件关联指向 mshta.exe，”打开方式”里显示的是一张白纸，很丑；
  2. 任务栏图标永远是 mshta 的白纸——因为任务栏按钮属于 mshta 进程，HTA 的 ICON 属性只改标题栏。

第三次：EXE 启动器 + 内嵌 HTA（最终形态）。

用 VB.NET 写一个薄启动器，把 HTA 和图标作为资源嵌进去，运行时释放到 %LOCALAPPDATA% 再启动。程序是真正的 PE 文件，文件关联、图标、任务栏全都名正言顺。

任务栏图标的问题在这里花了最多时间。跨进程 WM_SETICON 完全无效——图标句柄是进程私有的，发过去也读不出来；ie4uinit -ClearIconCache、SHChangeNotify 都改不了它。

最后的办法很”老派”：

让启动器自己建一个顶层窗口（WinForms），等 HTA 引擎窗口启动后，用 SetParent 把它挂成子窗口，去掉 WS_CAPTION / WS_THICKFRAME，补上 WS_CHILD，尺寸随宿主客户区联动。

这样任务栏按钮归属于 MdStudio.exe，图标、名称、分组全部正确，而渲染依然跑在真正的 HTA 引擎里，ActiveX 一点没损失。

中间还踩了个小坑：Process.MainWindowHandle 拿到的其实是内层的 frame 窗口（133138），不是顶层 HTA 窗口（133136），SetParent 直接打空，桌面上冒出两个窗口。改成 EnumWindows + GetWindowThreadProcessId + 类名精确匹配 HTML Application Host Window Class 才定位对。

三、做出来是什么样

界面是三栏：左边大纲，中间源码，右边预览。可以切成纯源码或纯阅读，分栏宽度能拖。

几个我自己最常用的：

  • 表格：点工具栏的表格按钮，弹出 WPS 那样的行列网格，划一下选 3×4，直接插进去；
  • 可视化改表：光标停在表格里，右下角浮出”编辑表格”，弹的是真表格，加行加列、改单元格，点应用自动按中文宽度对齐回写源码——竖线再也不会歪；
  • HTML 补全：输入 < 就出候选，↑↓ 选，Enter 确认，和 VS Code 一个手感；
  • 代码块：行首敲三个反引号回车，自动补闭合围栏；
  • 专注 / 打字机：专注模式只留正文，右上角有个半透明”退出”按钮；打字机模式让当前行永远停在编辑区 42% 的高度。

四、那些必须踩的坑

开发过程中真正卡住我的，都不是”功能不会写”，而是这些：

坑 1：HTA 默认跑在 IE7 文档模式。
addEventListener、getComputedStyle、Array.indexOf 全部不存在，页面一开就是脚本错误。必须加 <meta http-equiv="X-UA-Compatible" content="IE=edge">，再补一层 ES5 polyfill。

坑 2：marked is undefined。
内联的 marked 是 UMD 包，尾部用 this 挂全局。在 HTA 里 this 不指向 window，于是变量挂丢了。构建时把 }(this||...) 替换成 }(window);，问题消失。

坑 3：保存空文档必崩。
报错”参数类型不正确，或不在可以接受的范围之内”。查了半天，根因是 ADODB.Stream.WriteText('') 传空字符串会抛 0x800A0BB9——长度为 0 必炸，传一个空格反而正常。老组件的怪癖。

坑 4：命令行传入的中文路径被截断。
mshta 的 window.argument 遇到空格就断。改成 exe 先把 %1 写成 UTF-8 临时文件，页面启动时读走再删除，读不到才回退 window.argument。

坑 5：任务栏图标（前面说过，最费劲的一个）。

坑 6：改了 DefaultIcon，资源管理器图标还是旧的。
图标缓存以 DefaultIcon 的字符串为键。同一个路径指向旧 exe，缓存永远命中旧图。必须换路径（指向 %LOCALAPPDATA%\Programs\MdStudio\），再 SHChangeNotify(SHCNE_ASSOCCHANGED) 通知刷新。ie4uinit 那些命令基本没用。

坑 7：保存成功了，但用户不知道。
这是我自己用出来的问题。点了保存，状态栏文案没变，心里发虚。于是加了右下角轻提示（2.2 秒淡出）和状态栏时间戳，并且把状态拆成三种：

  • 未保存（强调色）——有改动没落盘；
  • 草稿已存 18:06——自动保存成功才显示；
  • 已保存 18:06——手动保存成功。

原来那个”打字 900 毫秒后无条件显示草稿已存”的伪状态被删了——它连保存失败都会报成功。

五、六套主题是怎么长出来的

主题不是一个下拉框加两套 CSS，而是一个色调系统。

六套基底：纸白、石灰、米黄、石墨、暖褐、墨黑；八个暖色强调色（默认赭橙 #b45309），从按钮、链接、选中态到大纲高亮、滚动条全部跟着走。

中途还做了一件对的事：把”主题”和”风格”两个入口合并成一个”外观”。原来两个按钮各管一半，改个背景色要去两个地方，纯属自找麻烦。

六、体积账

组成 大小
HTA 页面（含内联 marked、全部样式与逻辑） 123 KB
启动器（含内嵌资源、图标） 161 KB
图标（7 帧 16–256px） 12 KB

对比一下：一个 Electron 空壳大约 100–150 MB，也就是这个数字的 700 倍左右。

代价也是清楚的：

  • 渲染内核是 IE11，现代 CSS 用不了太多，得靠兼容写法；
  • 依赖系统保留 mshta.exe，某些企业策略禁用 HTA 就彻底跑不起来；
  • 首次运行会被 SmartScreen 拦一次。

对”打开写两行字”这个场景，我认为很值。

七、现在的状态

已经能日常用了：

  • 双击即开，也可以设为 .md 默认打开；
  • 桌面右键 → 新建，多一个”Markdown 文档”（也是程序里的一个开关，不需要手动改注册表）；
  • 自动草稿，崩了也不丢；
  • 内置快捷键手册，F1。

全部系统集成只写 HKCU，不需要管理员权限，也不动系统目录。
